# Evaluation harness — static vs AI-assisted adaptive rate limiting (Phase 5)

A **separate** evaluation system (spec §32–33) that answers one question with measurements, not
claims:

> Does the adaptive system improve protection **without** unnecessarily blocking legitimate clients?

It replays five deterministic traffic scenarios through a faithful **offline** model of the
production pipeline and compares two arms:

- **STATIC** — a fixed rate limit (capacity 100, refill 10/s), no agent.
- **ADAPTIVE** — the same limit, but the **real agent planner** (`HeuristicPlanner`) reacts every
  minute through a faithful mirror of the Phase 2 detector, the Phase 3 Policy Gate, and the
  Phase 4 closed loop (keep / revert).

Nothing is hard-coded: every number falls out of the run. The harness is offline and
deterministic — no Redis, no live gateway, no API key — so the result is reproducible and runs in
CI in a couple of seconds.

## Why offline?

The simulator is the Phase 5 "historical replay" idea (spec §29) taken to its conclusion: to
compare two policies on the *same* traffic we must replay identical requests under each, which a
live stack cannot guarantee. The offline engine mirrors the production logic exactly — the token
bucket mirrors `token_bucket.lua`, the detector mirrors the EWMA/z-score + `AnomalyRules`
thresholds, and the gate mirrors `PolicyGate` guardrails (evidence ≥ 2.0, ±50 % change cap,
absolute bounds, cooldown, action-rate cap, high-value human approval). The adaptive arm drives
the **same** planner the live agent uses.

## Run it

```bash
cd ai-agent
python -m app.simulation                      # prints the report, writes evaluation/results/
python -m app.simulation --out-dir path --quiet
pytest tests/test_simulation.py               # mechanics + per-scenario direction checks
```

(Or inside the agent image: `docker run --rm rate-gaurd-ai-agent python -m app.simulation`.)

## Scenarios

See [`scenarios/scenarios.md`](scenarios/scenarios.md). The five scenarios (§32) are: scraper
burst, legitimate traffic spike, slow-and-low abuse, noisy (high-value) tenant, and a sudden API
5xx spike — chosen to exercise every agent decision path (block, raise-limit, approval-gated
block, alert-only).

## Metrics (§32)

Per scenario, per arm: total requests, 429 rate, **legitimate requests blocked** (false blocks),
**abuse block rate** (abuse detected), **5xx served**, agent actions applied / rejected by the
gate / pending approval / alerts / rollbacks, **time-to-mitigation**, and **recovery time**.
